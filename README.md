# 镭页展陈·双语铭牌溢出预审

按实际排版空间和历史校样筛出需人工重排的双语展品铭牌。

模拟团队为 镭页展陈印前组 · 7 人。译审交稿后，印前员从排版软件逐一打印 1:1 纸样。固定框宽和字高常由不同模板继承，人工按新翻译列表全量复测。

- 同名版式有 13 类，历史溢出率差别大，长尾类别资料稀少。
- 中文字数与参考语字数无法直接比较实际可用行宽。
- 陌生语言组合常被当成普通样跳过，临到输出才补校。

输入双语译审清单的纸样参数、版式编号和历史实际溢出结果。 签发的重排与加校名单交给印前拼版员，最终依实际纸样裁定。

## 业务模块

| 模块 | 工作内容 | 核心实体 |
|---|---|---|
| 校样底稿 | CSV 校验、预览实测字段、以完整数据内容的 SHA-256 去重、追溯版本和下载原始数据 | 数据版本 |
| 预审计算 | 开班后按班次工时接单，由独立进程计算；从排队、成功或失败状态追溯 | 计算单 |
| 溢出清单 | 按业务字段查看度量、比较与排序，查看本班排入情况，下载计算结果 | 计算单及其结果 |
| 拼版交接 | 对结果样本作签发或暂缓，记录理由，导出本班已排样本并查看审计时间线 | 交接记录 |

## 算法及口径

**留一平滑目标编码 + 逻辑回归 + 工时排班**。仅在训练纸样上拟合版式与参考语组合的平滑目标统计。训练用留一编码、验证和待校应用完整训练映射，未知类别回退训练先验。两版模型（几何基准、目标编码）在同样的班次工时与排班规则下各排一次留出纸样，按实际查出的溢出张数择优，张数相同再比 Brier 分数。设置重排概率阈值；新组合即使概率低仍须补纸样。双类不足或字段缺失时终止计算。

录入参数 **重排概率阈值**，默认 0.6，允许范围 0.3–0.9。概率达到阈值进入重排队列。首次出现的版式或参考语仍需补纸样。

### 班次与排班

每张纸样在底稿里填预计耗时（分钟）。分析员先以**本班可用工时**开班，再由计算单接入班次：

- **多查出溢出**：择优后的模型按本班工时排班，训练未见的版式 / 参考语组合至少排一张；剩余工时用 0/1 装箱按溢出概率装满，尽量多查出溢出。工时不够时尽量少漏组，并在清单一并注明缺哪一组。
- **并发不超工时**：班次在接单时加行锁预留分钟，几张计算单共用同一份工时，合计永不超过班次工时。被拒的接单整笔回滚，不留半个占位。
- **重试不重复占位**：每张计算单只有一条预留；提交时携带 `request_key`，重复或并发重发同一个 key 只会返回原来的计算单，失败的同一单重发在原地重新排队，绝不二次占位。
- **插单重排不停工**：插单会从各单候选样本重新装箱。已开打纸样（`POST /runs/{id}/start`）保留工时；成功后已完成纸样固定不动；其余按概率填满，尽量不留闲置。
- **交接只导本班**：签发导出只包含签发样本与本班已排样本的交集。

演示集 `镭页_常设展铭牌_2026-11-25.csv` 由 `backend/src/business/demo.py` 用固定数据或固定随机种子生成，每张纸样的预计耗时按行数与占宽推算。工作台保留每次运行使用的输入版本、参数、结果和签审人。业务判断与排班都由服务端执行，前端图表直接读取返回的数值。

## 一天的工作剧本

1. 08:35 译审交出镭页_常设展铭牌_2026-11-25.csv。
2. 08:45 对照样本 192 条训练、48 条独立留出和 8 条待校，底稿逐张填预计耗时。
3. 09:00 分析员以 240 分钟开早班，再以 0.60 概率阈值建预审计算单。
4. 09:10 核对几何基准与目标编码两版模型的留出实查溢出张数和 Brier。
5. 09:15 铭牌 LY-P01 的高占位版进入重排，LY-P08 的新语言组合必须补纸样。
6. 09:25 第二张计算单插单，已开打的纸样保留工时，其余重新排入剩余工时。
7. 09:30 复核员签发 LY-P01，导出仅含本班已排记录的拼版 CSV。
8. 10:00 拼版员按待校意见做 1:1 样张，保留预测与纸样两套记录。

## 技术与配置

| 服务 | 技术与职责 |
|---|---|
| frontend | HTML/CSS/JS ES 模块，Nginx 静态页面与同源 API |
| backend | Python 3.11、FastAPI、SQLAlchemy、JWT |
| worker | Python 后台进程，使用 DB 的原子认领、租约与重试，输出 CSV |
| db | PostgreSQL 16，存账号、版本、计算单和审计 |
| redis | Redis 7，通知 worker 尽快拾取，任务状态由数据库持久化 |

`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 管理回环端口，`JWT_SECRET` 为签名密钥，`DB_PASSWORD` 为应用数据库口令，`COMPOSE_PROJECT_NAME` 控制该栈的命名空间。

本地 Python 开发可用 `docker compose up -d db` 启动关系库，并另起一个仅绑定回环的 Redis。Compose 内的 Redis 通过容器网络连接。用 Python 3.11 安装 `backend/requirements.txt` 后，进入 backend 目录，设置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET`、`ARTIFACTS_DIR`、`SEED_DEMO`，分别运行 `uvicorn src.main:app --reload`、`python -m src.worker`。ARTIFACTS_DIR 需已存在且由两进程共享。前端可使用 Compose Nginx 镜像并重建以加载修改，或用已有 Nginx 反向代理本地 Python 端口。

`backend/src/business/` 保存本题字段、生成器、算法和排班器（`scheduling.py`），`backend/src/services/` 处理资源生命周期（`shifts.py` 负责班次与工时预留），`backend/migrations/` 是初始关系模式，`backend/tests/` 为排班与接单的回归测试（`python -m pytest`），`frontend/src/` 按页面、API、会话、组件、路由及样式组织。前后端枚举分别在 `backend/src/constants/workflow.py` 和 `frontend/src/constants/enums.js`。角色用于 JWT 路由与表单权限，计算状态用于队列与结果页，签审决定用于交接页、审计和签发导出。
